# Dorey v0.2.2

本版本统一交付“修订 / 解释”评论分流、待接受修订的刷新恢复修复，以及版本与安装说明。

## 变更

- 评论支持“修订”和“解释”，默认选择修订；编辑评论时可以切换类型。
- 根据待提交内容显示“提交修订”“提交问题”或“提交全部”，并分别统计两类评论。
- 解释型评论由原 Agent 会话回答，Dorey 仅展示轻量回执，不重复显示解释正文。
- 纯解释请求保留原 Markdown，即使 Agent 意外返回改写内容，也不会产生可接受的文档修订。
- 混合提交先在原会话回答问题，再处理修订意见；有文档变化时才显示修订、差异和接受操作。
- Codex / TraeX 的请求提示及 foreground poll 输出同步携带评论类型和处理约束。
- 修复待接受修订在刷新后丢失的问题：有改动的结果在接受写回成功后才确认，刷新可恢复修订、差异和待处理评论；纯解释及无改动结果继续立即确认。
- 接受写回冲突保留待接受结果；写回成功后确认请求失败可重试。接受较新的方案会同时结束同文档、同目标的较早 completed 方案，避免旧方案再次出现。

## 兼容与边界

旧评论未携带 `kind` 时按 `revision` 处理；新解释评论使用 `kind: "explanation"`。非空“全文修订要求”也代表修订意图，因此与解释评论同时提交时允许产生文档修订。

原会话仍需保持 foreground poll；页面的“已回答”回执来自 Agent 返回结果，并不验证原对话中是否实际发出了答案。解释正文应由处理请求的 Agent 在原对话中提供。

接受修订仍执行原文件 hash 校验和原子写回；外部变更冲突时不覆盖原文件。队列仍持久化 completed 结果；有改动时 acknowledge 延后到接受写回成功，纯解释及无改动仍在结果展示后确认。结束评审协议保持不变。

## 安装与交付

需要 Node.js 22 和 npm；安装包通过 [Dorey v0.2.2 GitHub Release](https://github.com/hopeloop/dorey/releases/tag/v0.2.2) 提供，项目不发布到 npm registry。

```bash
curl -L -o dorey-0.2.2.tgz \
  https://github.com/hopeloop/dorey/releases/download/v0.2.2/dorey-0.2.2.tgz
npm install -g ./dorey-0.2.2.tgz
dorey --help
```

v0.2.1 仅有源码 Release；本版本提供与包版本一致的 npm tarball。完整功能、修复和发布准备通过 [PR #8](https://github.com/hopeloop/dorey/pull/8) 合入 `main`；[PR #9](https://github.com/hopeloop/dorey/pull/9) 保留刷新恢复修复的独立审查记录。

发布安装包从目标 `main` 提交的干净 checkout 构建；Release 附件的 SHA-256 和最终验证结果见 GitHub Release 正文。

### 已修复的发布阻塞

原候选在“混合评论返回 → 页面已显示修订 → 尚未接受即刷新”时丢失待接受结果，原因是结果展示时就 acknowledge，刷新只恢复未确认 submission。

DOR-P0-008 已在修复前复现失败、修复后通过，并覆盖写回冲突、确认失败后的恢复与重试、接受较新方案后不重放旧方案。修复复用现有持久化队列，不需要迁移存储格式。已经被旧版本 acknowledge 且未接受的历史结果不会自动恢复；本次保证修复版本处理的待接受结果可恢复。
